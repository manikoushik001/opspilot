# OpsPilot Failure Modes & Resilience Architecture

This document analyzes system failure modes, detection mechanisms, handling strategies, user experiences, and recovery paths across the OpsPilot stack.

---

## Matrix of System Failure Modes

| # | Failure Mode | Detection | Handling Strategy | User Experience | Recovery Path |
|---|---|---|---|---|---|
| **1** | **Database Failure / Connection Pool Exhaustion** | SQLAlchemy connection timeout / Health check failure | Async connection pooling with auto pre-ping and bounded max-overflow. Return HTTP 503 on pool exhaustion. | Friendly error banner: "Database temporarily busy, retrying..." | Automatic reconnection on pool availability; connection recycle timeout. |
| **2** | **Redis / Cache Outage** | Redis `ConnectionError` on rate-limit / Celery enqueue | Graceful degradation: Fall back to synchronous in-process task execution if Redis is unavailable. | Document processing completes directly with minor HTTP latency increase. | Redis restart; background job retries managed with Celery dead-letter queue. |
| **3** | **LLM Provider API Outage / Timeout** | `httpx.TimeoutException` or HTTP 5xx from OpenAI/Gemini | Catch LLM provider exceptions in `AIService`, log failure in `ai_interactions`, fallback to mock or mark conversation for `HUMAN_REVIEW`. | Safe fallback response: "Our automated assistant is temporarily experiencing delays. A support specialist will follow up shortly." | Exponential backoff retry with jitter; automatic circuit breaker. |
| **4** | **Embedding Generation Failure** | HTTP error or non-200 from embedding endpoint | Fail document chunk ingestion transaction; mark `KnowledgeDocument.status = FAILED` with explicit `error_message`. | UI displays red "Failed" badge on Knowledge Base document with retry button. | User re-uploads document or clicks retry once provider recovers. |
| **5** | **Low Vector Retrieval Similarity (< Threshold)** | `scored_chunks` empty or maximum similarity score < `RAG_SIMILARITY_THRESHOLD` | Grounding guard: Refuse to generate speculative answer. Auto-escalate conversation to `HUMAN_REVIEW`. | AI states: "I cannot find verified information regarding this in our business records. I have escalated this to our team." | Staff takes over conversation directly from inbox. |
| **6** | **AI Hallucination / Unsupported Claims** | `AIValidator.validate_grounding` detects claim mismatch or unreferenced entities | Invalidate draft answer before persisting or sending to customer; route to staff. | Customer receives polite escalation notice; staff sees original prompt and draft in inspector. | Knowledge manager uploads updated policy or course document to cover the knowledge gap. |
| **7** | **Prompt Injection Attack** | `AIValidator.detect_prompt_injection` matches attack regex signatures | Abort prompt execution immediately; flag `is_injection_suspected = True`; escalate conversation; log security event. | AI replies: "Your request contains prohibited instructions. A staff member has been alerted to assist you directly." | System prompt and database remain untouched; attack logged in `audit_logs`. |
| **8** | **Cross-Tenant Data Tampering (Header Spoofing)** | `get_current_business_membership` detects mismatch between user memberships and `X-Business-ID` | Reject immediately with HTTP 403 Forbidden. Do not execute SQL query. | "Access denied: You are not an authorized member of this business tenant." | Zero data leakage across tenant boundaries. |
| **9** | **Document Processing Failure (Corrupted PDF/TXT)** | `pypdf.errors.PdfReadError` or decoding exception | Catch parsing exception; mark `KnowledgeDocument.status = FAILED`; set `error_message`. | UI displays: "Corrupted PDF format. Please verify file integrity and re-upload." | User uploads clean document; system cleans up temporary storage files. |
| **10** | **Duplicate Action Submissions** | Button double-clicking or network retry | Controlled action state machine (`ai_actions.status` transitions from `PROPOSED` to `EXECUTED`). Idempotency check. | Subsequent clicks return already executed confirmation without creating duplicate follow-ups. | Transaction commits once with atomic status update. |
| **11** | **Network Timeout on Client** | Fetch timeout in `api.ts` | Axios/fetch timeout triggers client-side retry with notification toast. | Toast alert: "Network timeout. Please check your internet connection." | Client re-queries endpoint. |
